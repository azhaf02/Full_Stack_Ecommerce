# Cart & Checkout Requirements

## 1. Cart Persistence

- Logged-in users will have a persistent cart associated with their user account.
- Guest users will have a cart identified using a client-side cart token.
- When a guest user logs in, the guest cart items will be merged into the user's existing cart.
- Duplicate products/variants during cart merge should be combined by updating the quantity.

## 2. Cart Items

Each cart item will contain:

- Product
- Product variant
- Quantity
- Unit price

The backend will validate that:
- Quantity is greater than 0.
- Requested quantity does not exceed available stock.
- Cart item price is taken from the server-side product/variant data.

## 3. Cart Pricing

Cart pricing will be calculated in the following order:

1. Calculate item line totals.
2. Calculate cart subtotal.
3. Apply a valid coupon discount, if applicable.
4. Calculate tax according to the documented flat-percentage tax rule.
5. Calculate final total.

The final total must never be negative.

## 4. Coupons

A coupon can contain:

- Code
- Discount type
- Discount value
- Minimum order value
- Maximum discount
- Start date
- Expiry date
- Usage limit
- Per-user usage limit
- Status

The backend must validate that a coupon:

- Exists.
- Is active.
- Is within its valid date range.
- Meets the minimum order value.
- Has not exceeded its usage limit.
- Has not exceeded the per-user usage limit.

Invalid coupons must return a clear rejection reason.

## 5. Cart and Checkout Integration

The Cart and Checkout modules must use the same pricing calculation logic.

Checkout must consume the pricing result generated by the centralized pricing engine instead of performing a separate pricing calculation.

Before moving from Cart to Checkout:

- Cart item stock must be revalidated.
- Coupon validity must be revalidated.
- Subtotal, discount, tax and total must match the pricing engine output.

## 6. Main Cart APIs

The planned Cart APIs are:

- `POST /api/cart/items` — Add an item to the cart.
- `PUT /api/cart/items/{id}` — Update cart item quantity.
- `DELETE /api/cart/items/{id}` — Remove a cart item.
- `GET /api/cart/summary` — Get cart pricing summary.
- `POST /api/cart/coupon` — Apply a coupon.

## 7. Database Entities

The Cart module will contain the following database entities:

- Cart
- CartItem
- Coupon

Cart and CartItem foreign-key relationships to existing project entities will be implemented according to the finalized schemas provided by the respective module owners.

## 8. Dependencies

The Cart module coordinates with:

- Product/Product Variant module — product and variant references.
- Inventory module — stock validation.
- Authentication module — user cart and guest-to-user cart merge.
- Checkout module — pricing and cart-to-checkout integration.

## Implementation notes
- Current pricing engine uses a 0% tax rate by default; tax is therefore zero until the project confirms the applicable tax rate.
- Guest-cart token persistence and merging must be verified against the authentication flow before this module is marked complete.
- Coupon per-user usage limits must be enforced against persisted order/redemption records, not merely the coupon configuration field.
